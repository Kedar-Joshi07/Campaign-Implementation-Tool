## Implemented

- The new-campaign form defaults **explicitly** to v3 Buyer Similarity, while Advanced Purchase Probability sends the unchanged v2 request shape. Switching modes disables incompatible radios, removes probability/rank filters from v3 requests, hides the v2-only top-percent field, and invalidates prior preflight output. Each preflight carries a request/revision fence, so an old response cannot replace current-mode or edited-context results.
- The five v3 choices are minimum indices 50/60/70/80/90 **and above**. The visible explanation and accessible tooltip say that this is model-relative demographic distance to supported product buyer profiles, not purchase probability or percentile. The 80 minimum includes 90+; the v2 0.80 band excludes 0.90+.
- Options include actual all-history distinct attributed-buyer support per product, keyed by the governed source catalog version. Counts below 200 are identified as insufficient history; other products are only *potentially* supported until exact context/window preflight. No unverified product is represented as a ready profile. Mode-specific source/calibration messages remain separate.
- v3 preflight shows eligible prospects, validly scored pool, feature-coverage gaps, similarity-qualified, selected, and eventual exportable as separate values. Before generation, unknown counts are **Not available**, never zero. A genuine zero at the 0.90 minimum on the prepared 10-prospect fixture is shown as **No exact matches**, with 10 still shown as validly scored. The preparation action remains reachable when sources support it; no-import choices are labeled as needing imports. Stale, building, unsupported, and temporary-failure messages are separate.
- Saved v1/v2/v3 results retain their recorded selection wording. The v3 detail renders the 0–100 index, model method version, original products and demographic criteria, snapshot provenance/membership (when completed), and unavailable optional probability without presenting it as zero or a red similarity blocker. The legacy v1 Run Again link and existing retry/progress/history controls remain. Completed v2/v3 results can restore their own mode and criteria into a **new** search draft; historical runs are not rewritten.
- The v3 result download remains unavailable by design until Stage 14B-07 supplies its governed export contract. “Eventual exportable” is unknown until contactability checks, not inferred from selected count.
- An unsupported P3 fixture (199 distinct all-history attributed buyers, below the 200 floor) was also exercised through real API preflight in the browser; the UI shows the unsupported state and does not call it a valid zero.
- A browser-clicked **Prepare & Start Search** on a separate 10-prospect disposable database built a current v3 profile/generation and completed an immutable 10-member result while the database had **zero** purchase-probability calibration artifacts. The fixture result projection was explicitly pointed at its temporary artifact root, so currentness was verified without treating a wrong-root artifact lookup as stale.
